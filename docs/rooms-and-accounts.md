# CPT 联机与邮箱账号

联机使用 CPT 社区账号，与 Minecraft 登录账号分开。“联机 → 联机房间”集中提供加入和创建房间，不再有独立“创建房间”侧栏入口。进入房间后，该页收起创建和加入表单，只显示当前房间及其操作；退出后恢复表单。公开列表位于“联机 → 联机大厅”，不显示当前房间管理面板，从大厅加入成功后自动切换到联机房间。未登录用户不能查询大厅、创建、加入或连接中继。

## 邮箱配置

后台：https://craftpilot.tolike.cn/admin，登录原有管理密码后选择“邮箱配置”。

1. 填写 SMTP 主机、端口、用户名、密码或授权码、发件邮箱。
   后台内置 QQ、网易 163、网易 126 和网易 Yeah 预设，可自动填入主机、465 端口和直接 TLS；仍可选择自定义 SMTP。QQ 与网易需先在邮箱账号中启用 SMTP，并填写授权码，不是网页登录密码。
2. 通常 465 使用直接 TLS，587 使用 STARTTLS。端口选择会同步建议的 TLS 开关，具体以邮箱服务商要求为准。
3. 勾选启用并保存，然后在“测试邮件”发送邮件到自己的邮箱。
4. 测试成功后，启动器内邮箱注册和找回密码可使用，无需重建服务。

SMTP 需要支持 TLS 且证书有效。保存后授权码不回显，留空表示保留原授权码。未配置时验证码接口返回 503，不绕过邮箱验证、不创建测试账号。

更换 SMTP 主机、用户名或发件邮箱后必须填写新授权码，不会自动复用旧账号的凭据。切换预设不会自动保存或启用邮件服务。

SMTP 配置通过 AES-256-GCM 加密存入数据库，密钥在数据库卷的 `mail-key` 文件中，权限 600。备份脚本会同步保存密钥；恢复邮件配置需数据库和对应密钥同时存在。不要删除、公开或丢失该文件。

## 账号

邮箱验证码注册、邮箱密码登录、找回密码、注销会话和会话查询已实现。CPT 普通账号密码为 6 到 12 位（包含两端），注册、登录和重置密码统一校验，使用随机盐和 scrypt；后台管理员密码与 SMTP 授权码不适用此长度限制。登录令牌随机生成，服务端只保存 SHA-256 摘要，有效期 7 天。本地令牌使用 Windows 当前用户 DPAPI 加密存于 `CPT/community-session.dat`。

验证码为 6 位、10 分钟有效、单次使用，使用服务器密钥 HMAC 存储，60 秒发送间隔，每小时每邮箱最多 5 次，错误尝试最多 5 次。接口另有来源限流。重置密码后旧令牌失效；后台停用账号后账号会话和房间连接均失效。

## 联机流程

房主可以在 Minecraft 打开世界，选择“对局域网开放”，输入游戏显示的端口；也可选择“MC 服务器地址”，填写域名或 IP 与端口。后者通过房主运行 CPT 的电脑连接指定服务器，不从网站服务器访问该地址；只共享房主明确指定的游戏端口。

登录 CPT 后填写房间名称、是否公开和可选房间密码，创建房间。默认私密，勾选“公开到联机大厅”后其他已登录用户才能在大厅列表看到该房间。房间密码可留空，设置时为 4 至 32 位；与账号密码的 6 至 12 位规则分开。服务端只在内存中保存加盐 scrypt 摘要，不返回密码。

朋友登录 CPT，在联机房间输入房间号或邀请链接后点击“加入房间”；需要密码时勾选“房间有密码”填写。联机大厅默认显示公开房间列表，每行包含房间名称、房主、人数和状态，进入页面时自动加载，支持应用的 F5 刷新。顶部使用 PCL 原生搜索框，输入完整 16 位房间号自动搜索，也支持回车；房间号大小写不敏感，清空搜索恢复公开列表，刷新保留当前查询。私密房间不出现在公开列表，但完整房间号可以搜索到。点击房间才弹出详情与加入确认，有密码时在弹窗内输入；取消弹窗不会发起加入请求。搜索框旁提供原生刷新图标，不返回密码、邀请凭证或目标服务器地址。

大厅外观复用 PCL 原生版本列表的 `MyCard` 标题容器和 `MyListItem`：标题显示公开房间数量，列表采用 42 像素行高、左侧 Minecraft 图标、两行文字及原生悬停反馈。房间名过长时省略显示，悬停可查看完整名称，详情仍通过点击弹窗打开。

联机各页面手动刷新统一通过 PCL 的 `IRefreshable.Refresh`，侧栏的刷新图标、页面刷新图标及 F5 调用同一入口。联机大厅搜索框右侧增加刷新图标，保留当前搜索；联机房间刷新当前房间资料及已展开的地址管理，不退出或重建连接，加入者本地端口保持不变。操作中或确认弹窗打开时不重复刷新。

房主可复制邀请链接 `https://craftpilot.tolike.cn/room#房间号.随机凭证`。网页点击“打开 CPT 并加入房间”通过 `cpt://join#房间号.随机凭证` 唤醒 CPT，并进入联机房间。浏览器可能要求确认打开应用。新版 CPT 首次正常运行自动注册当前 Windows 用户的协议处理器，不要求管理员权限；需先解压并运行一次，移动客户端后再次运行以更新协议路径。未安装或未注册时，可使用网页下载入口，或复制完整邀请链接在客户端手动加入。

网页唤醒后，CPT 先弹出“是否加入此邀请房间”，确认后才加入。客户端未登录时也先确认，确认的邀请仅在内存中保留，登录或注册成功后继续加入，不重复询问；取消则清除待加入邀请。已在同一房间时显示当前房间，不重复加入。已在其他房间时显示当前房间名称、房间号和邀请房间号，询问“是否退出当前房间，再加入邀请房间”，仅点击“退出并加入”才离开，取消保持当前连接。邀请成功后联机房间显示房间名称、房主、人数、房间号和游戏入口，原创建/加入表单收起。已运行的 CPT 通过仅当前 Windows 用户可访问的命名管道接收邀请，不启动第二个房间客户端。邀请不自动启动 Minecraft，也不接受网页指定的命令、服务器目标或其他域名。

完整链接粘贴到“房间号或邀请链接”仍可免房间密码加入，需 CPT 登录。邀请凭证为 32 字节密码学随机数，放在 URL 片段，不进入网页请求路径、查询参数或访问日志，不写入客户端日志或持久化待加入队列；不出现在大厅和后台详情中。房主可以重新生成链接，旧链接和未用加入票据随即失效，已加入成员不被踢出。锁房、人数上限、踢人限制、账号停用不会被分享链接绕过。

房间关闭、房主断线、退出账号、账号被停用或服务重启后，原分享链接失效，未使用的加入票据也撤销。重新创建房间生成新的房间号和邀请凭证，旧链接不会恢复。网页打开时检查邀请有效性，已打开的页面每 15 秒及重新获得焦点时复查；失效时隐藏唤醒/复制操作并提示“邀请已失效”。因此网页状态可能延迟更新，但服务端在关闭后立即拒绝加入。网页检查只发送 `SHA-256(房间号.邀请凭证)` 摘要，不发送原始邀请凭证，不把摘要放进 URL。检查失败时不把邀请判为有效。

加入成功后生成 `127.0.0.1:随机端口`，可复制到 Minecraft 多人游戏中的直接连接，也可选择匹配客户端后点击“进入游戏”。房主也可以点击“进入游戏”连接自己的目标。联机页面已移除独立的“直接连接 MC 服务器”表单，创建房间时仍可选择 MC 服务器作为共享目标。游戏账号由原 Minecraft 账号系统处理；客户端版本、加载器和模组必须与目标兼容。

房主在当前房间中可修改名称、公开状态，保留、更换或取消密码。修改密码撤销未使用的加入票据，但不主动踢出现有成员；要断开已加入成员，使用后台成员操作或关闭房间。邀请网页仅在用户点击后请求打开应用，不在页面加载时自动唤醒。

房间号由密码学随机数生成，实际连接还使用登录校验、30 秒单次连接票据。局域网世界模式固定转发本机回环地址，服务器模式仅转发房主指定地址；加入者不能指定转发目标，本地入口只监听回环。房主选择服务器模式前需确认共享该端口，禁止把邀请链接公开传播给不可信用户。

使用 `ClientWebSocket` 和开源 `ws` 库，通过 `wss://craftpilot.tolike.cn/api/rooms/socket` 中继 TCP 游戏数据；不是 P2P，也不依赖原版 PCL 已关闭的联机服务。不自动扫描局域网世界，不支持 Bedrock UDP、语音 UDP 或跨版本适配。

每房间最多 8 人（含房主）、32 条游戏连接，每加入者最多 8 条连接，全服务最多 256 条转发连接。单消息 64 KiB、单连接排队最多 512 KiB、每房间数据上限约 8 MiB/s；超过限制会断开对应连接。

房主退出、掉线、账号失效或服务重启会关闭房间。房间、公开状态、密码与邀请链接的内存状态不持久化，重启后需重新创建。切换 CPT 页面不退出房间；退出 CPT 会提醒。加入者对指定游戏端口具有普通网络访问能力。公开房间意味着允许其他登录用户尝试加入，请配合房间密码和管理限制使用。

## Minecraft 域名

`前缀.cpts.pw` 是 Minecraft Java 的游戏地址，不是网页链接，不带 `https://`。朋友在 Minecraft“多人游戏 → 添加服务器”填入即可查询状态和连接，不需要登录 CPT 或安装 CPT。

房主在 CPT 登录后进入“联机房间”，创建指向局域网世界或 MC 服务器的房间，在当前房间点击“管理 Minecraft 地址”展开地址设置，申请自定义前缀或留空随机生成，再点击“发布到当前房间”并确认。随后复制“游戏地址”给朋友。地址管理集中在当前房间内，不在大厅或独立页面显示。目标游戏、房主电脑网络和房主 CPT 均需保持在线。房主本地进入游戏仍连接原目标地址。

- 前缀为 3 至 32 位字母、数字或连字符，首尾不能为连字符，大小写统一转为小写；系统名称保留。
- 前缀全局唯一，每个 CPT 账号最多保留两个，数量和重复检查在数据库事务内完成。
- 前缀归属持久化；房间关闭、房主断线、退出账号或账号被停用后停止转发，但不会自动释放前缀。
- “取消发布”停止转发并断开该地址现有连接，前缀仍保留；“释放前缀”同时取消发布，其他用户可以重新申请。
- 两个前缀可以发布到同一房间，必须指向同一目标。不支持在一个房间内发布两个不同游戏目标。
- Minecraft 域名入口无法校验 CPT 登录或房间密码，公开发布前需确认。目标 Minecraft 的正版验证、白名单和封禁规则仍生效，管理员锁房拒绝新的公网连接。
- 仅支持 Java TCP；不支持 Bedrock UDP、跨版本或自动补齐模组。实际玩家人数由目标游戏管理，公网玩家不计入 CPT 房间成员数量。

游戏端口为 TCP 25565，泛解析 `*.cpts.pw → 103.116.247.92`。网关读取有大小和超时限制的第一段握手以选择前缀，之后透明转发，不接管 Minecraft 账号认证。目标连接由房主客户端发起，公网连接者不能指定其他转发目标。每来源每分钟最多 60 次连接、公网 TCP 最多 256 条，另受每房间 32 条连接与共享流量限制。

## API

- `GET /api/auth/status`：邮箱注册可用状态。
- `POST /api/auth/code`：`email`、`purpose`（`register` 或 `reset`）。
- `POST /api/auth/register`：`email`、`nickname`、`password`、`code`。
- `POST /api/auth/login`：`email`、`password`；返回用户和 Bearer 令牌。
- `GET /api/auth/me`、`POST /api/auth/logout`：需 Bearer 令牌。
- `POST /api/auth/reset`：`email`、`password`、`code`。
- `POST /api/rooms/create`：`port`；`join`：`code`；`stream`：`code`；`leave`：空对象。全部需 Bearer 令牌。
- `create` 额外接受 `title`、`public`、`password`、`targetKind`（`lan`/`server`）；目标地址只保留在房主客户端。
- `GET /api/rooms/lobby?code=`：留空查询公开在线房间，完整房间号可搜索私密房间。
- `POST /api/rooms/invitation-status`：无需 CPT 登录，提交 `code` 和 `proof`（邀请片段的 SHA-256 十六进制摘要），仅返回 `valid`、`expired` 或 `unavailable`，不返回私密房间详情。检查不产生加入票据；实际加入仍需 CPT 登录与邀请校验。
- `GET /api/rooms/mine`：当前房间；仅房主返回分享链接。
- `POST /api/rooms/settings`：房主使用 `code`、`title`、`public`、可选 `password`、`rotateInvite` 修改；省略密码保留，空字符串取消。
- `join` 可附 `password` 或 `invite`；邀请凭证正确时免房间密码。加入接口另有限流。
- `GET /api/game-addresses`：当前用户保留的前缀、游戏地址和发布状态；`POST`：`prefix`，空字符串随机申请，返回 201；需 CPT 登录。
- `DELETE /api/game-addresses/:prefix`：释放自己的前缀并关闭对应公网连接，JSON 请求体为空对象。
- `POST /api/rooms/publish-address`：房主使用 `code`、`prefix`、`confirmed: true`、`targetHost`、`targetPort` 发布；目标需与房主创建房间时的实际目标一致。
- `POST /api/rooms/unpublish-address`：`prefix`，取消自己的地址发布但保留归属。
- WebSocket：`/api/rooms/socket`，使用 `cpt.<ticket>` 子协议，票据不放在 URL。
- 后台邮件 GET/PUT `/api/admin/mail`、POST `/api/admin/mail/test`，用户 GET `/api/admin/users`、PATCH `/api/admin/users/:id`，房间 GET `/api/admin/rooms`、DELETE `/api/admin/rooms/:code`。写操作需后台会话、正确 Origin 和 CSRF。

用户搜索分页、会话撤销、批量管理、房间详情与成员操作、审计接口见 `docs/admin-management.md`。

后台统计按注册账号 ID 去重，展示累计注册用户、过去 24 小时及 30 天有登录/鉴权活动的账号和每日新增/活跃。一个账号的多设备、多会话不重复计数；不代表真实自然人数。用户日活明细保留 90 天，匿名安装心跳不会增加用户统计。注销不删除当日已经发生的活动记录。

只在明确配置的 `TRUSTED_PROXY_IP` 与请求对端完全一致时使用代理最后一个 `X-Forwarded-For` 地址限流；不能随意信任公网代理头。代理容器地址变化时需同步此配置。

生产部署保留原数据库、管理密码和 HTTPS 代理，不创建假用户或配置假 SMTP。完整 .NET 房主/加入者客户端与 Node 后端的双向 TCP 回环已验证；真实邮箱投递及两台设备上的 Minecraft 实战仍需在 SMTP 配置后验证。

## 第三方来源

邮件投递使用 [Nodemailer](https://github.com/nodemailer/nodemailer)，MIT-0 许可。WebSocket 中继使用 [ws](https://github.com/websockets/ws)，MIT 许可。生产镜像保留 npm 包内的许可文件，依赖通过 `package-lock.json` 锁定并执行安全审计。客户端使用 .NET 自带的 ClientWebSocket 与 TCP，不安装或改名上游 PCL 联机引擎。

Minecraft 握手解析使用 [minecraft-protocol](https://github.com/PrismarineJS/node-minecraft-protocol)，MIT 许可；不自行实现完整游戏协议。隔离测试已覆盖真实 .NET 房主、Minecraft 1.16.5 状态查询/压缩登录和双向 48 KB 加密数据，公网端口、未申请前缀拒绝和服务重启也已验证。两台电脑上的图形版 Minecraft 实际游玩尚未验证。
