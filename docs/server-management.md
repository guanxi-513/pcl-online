# CPT 方舟领航：服务器部署与管理

项目名称：**CPT 方舟领航**。功能副标题：**Minecraft 启动与服务器管理工具**。

本实现直接接入现有 PCL 主程序，保留原版账号登录流程。顶栏为“启动”“服务器”“我的服务器”等，支持保存多组连接。

## 服务器选择与部署进度

- “启动”保留游戏启动和版本选择，账号输入已集中到“设置 → Minecraft 账号”，启动页只显示默认账号摘要及管理入口。
- “服务器”合并第三方游玩服务器和已部署的“我的服务器”，支持名称/地址添加、修改、删除及加入，默认端口 25565；列表状态检测不需要 SSH，不显示部署或社区资源。
- 列表每 30 秒异步检测 Minecraft Java 状态，显示版本、玩家数及状态查询总往返耗时；手动刷新同样可用。离开页面暂停轮询。
- 状态检测基于 MCStatus.NET 的 .NET Framework 兼容移植，来源和许可见 `PCLCS/Server/Vendor`。支持直接域名、IP、[IPv6]:端口；域名未指定端口时使用 DnsClient.NET 解析 Minecraft SRV 目标，显式端口不被 SRV 覆盖。状态握手保留玩家输入的原域名用于代理路由，使用标准协议号并兼容旧协议。
- 状态查询同时尝试域名的 IPv4/IPv6 地址，玩家人数不公开时显示“人数未公开”。TCP 已连接但状态不可用时提示仍可尝试加入，查询未连通也不等同于游戏一定不可进入，不禁用加入操作。
- “我的服务器”保留自建服务器部署管理，已部署条目提供客户端整合包导出图标。它们同时出现在“服务器”列表并标注“我的服务器”，方便直接进入游戏及账号设置。
- “更多”仅保留帮助和关于与鸣谢，已移除百宝箱、反馈和新功能投票菜单以及对应隐藏选项。
- “我的服务器”保留无顶部操作栏的列表样式，右下角 PCL 原生悬浮加号进入部署服务器，暂无服务器时同时显示“添加服务器”按钮。每条记录提供删除图标，确认后只移除本地记录和该记录的账号绑定/任务缓存，不停止远端服务器、不删除世界或客户端文件；正在部署的记录不能删除。
- 点击已部署服务器直接进入管理页，默认打开运行状态；管理模式只有连接设置、运行状态、资源、配置、玩家和官网选项，不提供重复部署按钮。
- 管理页默认打开“服务器概览”，显示连接地址、状态、在线玩家和待重启变更；启停主按钮根据查询结果切换，日志默认折叠。缺少密码时通过遮蔽输入弹窗提示，不要求先寻找连接设置。
- 模组/插件页先显示已安装和待安装项，勾选“添加模组或插件”后展开搜索；通过链接安装、Java 参数和原始配置文件默认收起。
- “游戏与设置”提供人数上限、难度、游戏模式和白名单表单，读取实际配置后才能保存。保存要求先停服，自动备份并保留 RCON 密码等敏感设置。
- 软件关于页和官网均有“支持 CPT”爱发电入口：`https://afdian.com/a/HUASQlaodaHH`，原作者署名和赞助入口仍保留。CPT 增补内容由 HUASQ 维护，原版与第三方版权不变。
- 添加服务器与悬浮加号进入独立的“部署服务器”页面。已删除管理/部署页顶部重复的服务器下拉框及新建、保存、删除、进入游戏操作区；连接设置内保留保存功能。
- 正在部署的服务器单独分组，显示当前步骤与阶段进度。点击条目进入部署详情，设置图标进入服务器管理。
- 部署页实时显示子步骤、最近输出时间、下载/上传实际字节数、总量与速度；总体采用五个实际完成阶段，不把它当作耗时百分比。下载细进度由实际字节计算，未知总量、安装和启动等待使用动态等待条，完成才显示全部阶段完成。平滑动效跟随新数值，不自行增长百分比；失败停止等待效果。
- 部署事件与只读远端终端分为两个视图，步骤列表默认折叠，日志支持跟随输出、暂停滚动和复制，最多保留 2000 行。远端代理通过独立、限量 JSONL 文件实时传回，最终结果继续由独立 JSON/退出码校验；安装器输出和启动日志可见，不提供交互 shell，也不展示 SSH/root 密码或生成的 RCON 凭据。日志通道中断不假定部署成功。
- 部署页提供“暂停部署”和“继续部署”，保持同一个任务，不重新创建部署。“正在等待安全暂停点”表示请求尚未生效，只有本地检查点或远端代理确认后显示“部署已暂停”，暂停时冻结等待动效、保留日志/文件/SSH。下载在读取下一段前暂停，防火墙命令、包管理器、解压和安装器等不可中断操作先执行完当前步骤，随后暂停；不使用进程强停，也不暂停已启动的 Minecraft 游戏进程。继续删除远端暂停标记并恢复后续步骤。部署失败/完成后隐藏按钮，暂停期间仍禁止删除部署记录。关闭客户端不等于可恢复暂停，不支持跨客户端重启续传；远端暂停最多 24 小时，超过上限停止并按代理逻辑清理。控制通道中断自动重连，不把未确认状态宣称为已暂停。
- 第二阶段检测并复用已有兼容 Java，Fabric Loader 与 Installer 元数据并行读取以减少等待；真实耗时仍受远端网络、Java/服务端大小、安装器和磁盘限制。当前日志通道在代理环境准备完成后开始轮询，系统包管理器的完整交互终端不转发。以上已在本地 SSH/SFTP 模拟与下载/界面测试中验证，未在用户真实服务器进行速度基准测试。
- 部署详情沿用游戏启动页的 MyLoading 动画、左侧阶段进度和右侧日志布局，支持返回列表继续查看其他服务器。
- 部署任务由独立 LoaderTask 运行，不依附管理页面。切换页面不会取消任务；密码只在本次任务内存中使用，结束后清除。
- 进度按连接、环境/下载、启动、等待运行、完成五个阶段更新，不代表字节级下载百分比；失败显示失败前阶段，不显示虚假的 100%。
- 列表中的运行状态来自本次操作或查询结果，不会在没有密码时自动发起 SSH。未查询时显示“状态未查询”，重新打开软件后需查询最新状态。
- 关闭整个启动器不会保证远程部署流程继续完成，请等待任务结束后退出。

## 继续失败部署

失败详情提供“继续上次部署”，进入连接页重新填写 SSH/提权密码后确认；服务器连接页也有同名入口，重启 CPT 后仍可使用。续部署只在再次取得 root 权限后执行。

- 已有 `.cpt-server.json` 且 Java/启动入口有效时识别为已安装服务器，跳过 Java、支持库及安装器下载，从运行状态检查继续。已运行或启动中的服务器不重复启动、不停止，未运行则重试启动、等待 RCON 就绪、生成并同步客户端配置包。
- 未完成安装的新任务在远端 `.cpt-server/deployment-history` 按目标目录保存白名单部署参数，不保存 SSH/root 密码、上传票据或实时控制参数。续部署读取原参数，不采用当前页面随意更换的版本；在独立暂存目录重新完成安装。
- 部署下载的已校验文件按算法/摘要缓存在 `.cpt-server/artifact-cache`，续部署重新计算摘要后复用，损坏时删除并重新下载；没有官方摘要的动态文件不缓存，半下载文件不做断点续传。缓存仅用于完整文件复用，安装器内部不支持任意指令断点恢复。
- 无已安装配置、无历史记录或未知非空目录时停止，不覆盖世界。旧版安装阶段失败时没有留下历史和缓存，无法补造断点；旧版安装完成但启动失败的目录可直接识别。未完成的本地 ZIP/JAR 导入需重新选择原包；安装完成的导入服务器可跳过安装继续启动。
- 暂存失败内容仍清理，安装成功文件、世界、RCON 设置不因继续而重置。新功能不修复游戏本身启动错误，若再次退出会继续报告当前日志原因。缓存会占用远端磁盘，可在所有部署任务结束后由管理员清理对应缓存目录。

## 使用顺序

Minecraft 账号统一在“设置 → Minecraft 账号”管理，支持离线、微软官方账号、Authlib-Injector 和统一通行证。添加后可设为默认。点击“服务器”中的条目进入详情，选择“使用默认账号”或为此服务器指定账号，再进入游戏；自建服务器详情保留服务器管理快捷入口。

账号认证复用 PCL 的 `McLoginMsLoader`、`McLoginAuthLoader`、`McLoginNideLoader` 和原 Java 认证补丁下载，官方授权仍需要原微软 Client ID 配置。LittleSkin 提供独立选项并固定认证根地址 `https://littleskin.cn/api/yggdrasil`，调用同一个 Authlib-Injector 登录加载器；可保存账号或验证登录，角色选择沿用原 PCL 流程。账号密码与刷新令牌存储位于启动器旁 `CPT/accounts.dat`，使用 Windows 当前用户 DPAPI 加密。复制到其他 Windows 用户或机器不能直接解密，应重新授权；服务器列表只存账号 ID，不存密码。每次启动锁定所选账号快照，切换第三方认证站会清除旧缓存。未设置或删除默认账号时不会自动挑选其他身份。

微软登录配置优先读取 `CPT_MS_CLIENT_ID`，兼容 `PCL_MS_CLIENT_ID`，GitHub 构建可由 `CLIENT_ID` 配置注入。公开源码和本地构建不包含官方 PCL 发行包的实际配置。Client ID 缺失时在设备代码和刷新令牌请求前明确报错，不发送空参数；设备代码轮询固定使用同一次授权请求的应用 ID。此校验修复不代表真实微软/Minecraft 授权已验证，发行者仍需提供适用于该应用的有效 Client ID。

## 独立运行与官网

- CPT 使用 `CraftPilot_SingletonMutex`、`HKCU/Software/CraftPilot` 和默认 `%TEMP%/CraftPilot` 缓存，与官方 PCL 单实例标识、注册表和默认缓存隔离。这些兼容标识不随展示名称修改，避免丢失现有账号与服务器配置。CPT 自身仍限制单实例；可以与 PCL 同时运行。
- 首次启动仅在旧 `PCLDebug` 存在 `ServerProfiles` 标记时迁移已有设置，不删除或写回旧命名空间。网页地址、旧自定义缓存不迁移，防止共享旧缓存。旧 CPT 的 `PCL/accounts.dat` 复制至 `CPT/accounts.dat`，保留原文件，不覆盖新文件。
- 启动器配置、日志、自定义主页等使用程序旁 `CPT/`；核心用户数据使用 `%AppData%/CPT/`；游戏文件夹索引使用 `CPT.ini`；每个游戏版本的设置和图标使用 `CPT/`，不写入 PCL 的同名文件。首次只读复制旧版本设置，后续保存与清理仅针对 CPT。共同游戏目录中的 Minecraft 原生文件仍可能产生竞争，不建议两个启动器同时安装或运行同一版本。
- 官网和更新接口固定为 `https://craftpilot.tolike.cn`。关于页与“设置 → 其他”保留检查更新入口，读取网站后台发布的迅雷分享链接。未发布更新时显示暂无更新，不自动下载或替换。
- 服务器管理的“官网与更新”页面已移除。安装量统计开关移到全局设置，默认关闭，原全局匿名数据开关仍会阻止上报。
- “我的服务器”、部署表单和部署进度使用无侧栏布局；管理功能在主内容区通过运行状态、模组与插件、服务器设置、玩家管理、连接信息标签切换。列表进入时及数据变化时自动刷新，也支持 F5。
- 顶栏“下载”与“联机”为独立入口。“下载”提供自动安装、Mod、整合包、数据包、资源包和光影包；“联机”侧栏包含“服务器”“联机房间”“联机大厅”。联机支持公开/私密、房间密码、完整房间号搜索、免房间密码的邀请链接，以及局域网世界或房主指定 MC 服务器目标，详见 `docs/rooms-and-accounts.md`。
- 启动页、服务器账号选择和账号设置均使用同一个账号头像模板：登录方式、皮肤头像、角色名、账号名。官方、LittleSkin、Authlib-Injector、统一通行证和离线账号均支持；角色名与 UUID 在登录完成后保存，皮肤失败时使用默认头像。隐私隐藏账号名设置仍生效。

本地账号管理、加密及页面测试不等于真实微软/第三方认证联调；真实授权、角色选择和加入服务器仍需用户在软件中完成。

1. 服务器提前启用 SSH/SFTP，填写地址、端口、用户名和密码。已移除私钥连接选项。
2. 默认自动检测系统，使用 SSH 用户主目录中的 `CraftPilot/server`，自动匹配 Java 并按可用内存配置。需要指定目录、Java、内存或游戏端口时打开“高级设置”。
3. 测试连接，将显示的 SHA256 主机指纹与服务器管理员核对后明确确认。之后指纹变化会再次警告。
4. 选择 Vanilla、Paper、Fabric、Forge 或 NeoForge。Minecraft 与加载器版本点击“选择版本”，通过 PCL 的已有加载器和列表控件获取；无需手填。Paper 版本来自 Paper 官方接口。
5. 阅读 Minecraft EULA 并勾选同意，点击“部署并启动”。确认后程序安装环境、配置服务器、防火墙并自动启动，等待 RCON 可用后才显示部署完成。
6. 完成后显示游戏地址。如云平台安全组拦截连接，请在平台控制台放行游戏 TCP 端口。程序不能代替用户修改云平台安全组。

### 远端 DNS 失败

`urlopen error [Errno -3] Temporary failure in name resolution` 来自远端部署代理：SSH 可以连接，但远端服务器无法解析下载域名。电脑能加载版本列表不代表远端服务器可联网。

代理对临时 DNS、网络超时和连接中断最多尝试 3 次（间隔 1、2 秒）。文件重试重新下载到 `.part` 并重新校验，不覆盖有效文件；永久域名错误、TLS 证书、HTTP 拒绝、校验失败和磁盘错误不会被盲目重试。最终错误显示下载域名及远端排查建议，不输出 URL 查询参数，不修改系统 DNS、不关闭 TLS 校验。

若持续失败，需要在实际目标服务器上处理网络：Linux 检查 `getent hosts 域名`、`/etc/resolv.conf`、默认网关及 DNS 服务；Windows 检查 `nslookup 域名` 和网络适配器 DNS。虚拟机还需确认 NAT/桥接和外网访问正常。DNS 地址按服务器所在网络配置，不能在未知网络中自动覆盖。修复后重新部署即可，失败任务会清理自己的暂存目录，不需要删除已有世界或服务器。

### 软件内检测与修复

连接设置提供“检测并修复网络”按钮，部署前也会自动检测。检测在目标服务器执行，覆盖默认路由、Mojang、Adoptium 和所选服务端域名及 HTTPS；不是用运行 CPT 的电脑代替远端检测。

DNS 失败时，只有检测到可用路由、至少一个公网 TCP 探测成功且识别到支持的网络管理方式，才弹出“修复并复测”确认。弹窗显示目标主机、网卡、DNS 候选 `223.5.5.5` 与 `1.1.1.1`，说明其他程序和内部域名可能受影响。取消后不修改 DNS、停止部署。

Linux 支持有 `resolvectl` 的 systemd-resolved，或未由网络管理器维护的普通 `/etc/resolv.conf` 文件；后者要求 root。Windows 使用默认 IPv4 路由对应网卡的 DNS 设置，要求管理员权限。systemd-resolved 修改是运行时设置，网络重连或重启后可能恢复。

修改前备份到 SSH 用户主目录 `.cpt-server/network-backups/`，修复后复测；失败恢复原 DNS。Windows 原配置为自动 DNS 时按自动设置回退。自动回退失败会弹窗报告备份位置，需管理员恢复，不继续部署。普通文件保留 search/options 信息，不覆盖已发现的并发更改。

默认路由缺失、公网探测均失败、TLS/HTTP 异常、未知网络管理器及权限不足不会通过修改 DNS 强行解决。程序不修改默认网关、不重启网卡、不关闭证书校验、不修改防火墙来“修复网络”。外网探测失败也可能来自目的地址被限制，因此提示是诊断而不是绝对断网判定。
7. 主页选择已部署服务器。没有本地客户端时点击“下载客户端”，完成后按钮变为“进入游戏”。每次进入前拉取当前服务器配置，必要时安装新配置对应的客户端，再按 PCL 原登录和启动逻辑进入服务器。

## 客户端配置与整合包

- 部署完成后自动生成 `.cpt-client.mrpack`，并拉取到本机 `CPT/ServerClients/`。主页提供导出 `.mrpack`，其他 PCL 或支持 Modrinth 格式的启动器也可安装。
- 配置包含 Minecraft 和实际服务端加载器版本；Paper/Vanilla 客户端使用原版，插件不会打包到客户端。
- 通过已安装 Mod 的 SHA-1 查询 Modrinth，核实版本、加载器与客户端支持。客户端 required 项自动包含，纯服务端或 optional 项默认不包含。
- required 客户端依赖递归解析并加入包。未知手动 JAR、未知环境需求或不兼容依赖列入 unresolved，自动客户端同步会阻止并提示管理员核对。
- 不复制服务器世界、账号数据、`server.properties` 或服务器配置目录。当前同步的是游戏、加载器和必需 Mod 元数据，不盲目复制可能含密钥的服务器配置文件。
- 下载客户端复用 PCL `ModpackInstall`，创建服务器 ID 和配置指纹对应的独立版本，不覆盖已有玩家版本。每次进入先校验最新配置，变更则安装新的独立版本。
- 进入前检查客户端必需 Mod 的文件和 SHA-1，缺失或损坏的文件使用 PCL 下载器补齐后再启动。
- SSH 密码仍仅在本次同步中输入，不保存；普通玩家无需获得 root 密码，可由管理员导出生成的 `.mrpack` 供玩家安装。当前没有另行公开配置下载服务。
- 版本选择默认显示正式/稳定版本，仍可切换快照和测试版本。Fabric/Forge 复用 PCL 加载器；NeoForge 先按游戏版本查询官方接口，失败后使用 PCL 镜像加载器。

## 自动环境补全

网络修复确认与结果弹窗使用异步等待，不在 UI 线程嵌套阻塞循环；确认后显示备份、DNS 修复与复测进度，取消不会修改 DNS 或继续部署。公共文本/密码/选择弹窗只由等待调用方管理模态进入与退出，避免关闭时重复 PopModal 导致输入状态异常。回归测试覆盖连续弹窗、界面心跳、确认/取消、离线/成功报告，以及密码和选择弹窗取消后的模态状态；不以这些本地测试替代真实远端 DNS 修复验证。

- Linux 新建部署默认 SSH 用户为 `root`，提权方式默认 `sudo`。部署前通过远端 `id -u` 判断权限，UID 为 0 直接执行；非 root 优先尝试 `sudo -n -u root -- id -u`，需要密码时单独询问当前 SSH 用户的 sudo 密码，通过带 PTY 的 `sudo -S -k` 执行并再次核验 UID 为 0。手动选择 `su` 使用 root 密码；“自动检测”优先 sudo、无 sudo 工具时选 su，不自动把 sudo 密码尝试给 su。失败或取消不部署。密码不拼进命令、不放进环境变量，关闭终端回显后只在对应密码提示后发送，不写入连接配置；页面离开或部署任务结束清除内存引用。部署、启动与 root 管理操作保持同一提权方式，不修改 SSH 登录身份。Windows 仍使用所配置的 SSH 用户及其权限。
- `UseSu` 仅保存后续管理需要提权的标记，`RootPassword` 不参与 JSON 保存；后台部署持有独立的连接快照，页面离开不清除运行任务所需凭据，任务结束清除。su 登录后显式使用原 SSH 用户的 HOME 寻找上传请求，根目录缩写也按原用户解析。root 生成的客户端配置包通过随机 root 临时目录供 SFTP 下载，完成后删除，且仍校验长度和摘要。验证包括本地模拟 SSH 的 root 直连、su 成功、错误密码及缺失 root 密码阻断；尚未在真实 Linux/PAM 环境中完成部署实测。
- su 命令 stdout/stderr 先隔离到 root 创建的临时目录，stdout 以 Base64 在随机起止标记之间传回，避免登录提示、终端颜色及换行处理污染 JSON；退出码单独校验，命令结束清理临时文件。有效代理错误继续显示具体原因；返回非 JSON 或损坏编码时明确停止，不再裸显示“Error parsing comment”。该修复已用本地 SSH 模拟验证，尚不能据此确认所有远端环境可成功部署。

- Linux：安装或验证 Python 3.10+。缺失时支持 apt/dnf；需要 root 或已经配置的免交互 sudo。系统包管理器不受支持时明确报错，不自动猜测安装命令。
- Windows：在 SSH 用户主目录 `.pcl-server/python` 安装隔离的 Python 3.12.10，不修改全局 PATH。Windows 服务端需 x64、PowerShell 和 SFTP；SSH 的默认目录必须与用户主目录一致。
- 按 Mojang 版本元数据自动选择 Java，也可指定 Java 大版本和远端可执行文件路径。低于游戏所需版本时拒绝部署。现有兼容 Java 可复用，否则从 Adoptium 下载独立 JRE。
- Java 解压支持官方 Adoptium TAR 包中的内部许可证文件链接：在全包验证后将符号链接/硬链接展开为包内普通文件，不在部署目录留下链接。继续拒绝绝对路径、越界路径、循环/悬空链接、链接目录父级、设备/FIFO、重复条目及多个顶层目录；限制条目数和展开体积，移除 setuid/setgid 权限。解压成功且存在 Java 可执行文件后才发布运行环境，失败清理暂存内容。同版本 Java 21 官方摘要校验和真实压缩包解压已在本地验证，Linux 实际执行仍需远端部署验证。
- Java 与官方服务端文件由目标服务器上的 Python 直接访问源站 HTTPS 链接下载，校验在远端执行；不通过用户电脑或 CPT 网站/联机网关中转。日志显示来源主机，不显示含令牌的完整 URL。本地导入 ZIP/JAR 是例外，需要 SFTP 上传；客户端配置包为小型清单，部署结束后从服务器拉回，不代表服务端下载被中转。默认 sudo 不保证网络提速，真实速度受远端到源站链路及源站限制影响。
- 支持的已校验资源自动加入国内镜像候选：Minecraft Java 原版服务端、Forge/NeoForge 安装器使用 BMCLAPI；Adoptium 的同版本、同架构 JRE 使用清华 TUNA。每个文件由远端并行读取候选的前 128 KiB（含 DNS/TLS/首包耗时），探测子进程最多 5 秒，按实测吞吐排序，不按客户端 ping 或静态优先级选择。日志显示候选采样速度和选中的主机。测速只是当时的小段采样，不能保证整个下载始终最快。
- 多线路正式下载读取超时为 15 秒，HTTP/网络失败、HTML 响应、摘要不符或截断文件会切换下一候选，失败文件只写 `.part`，已有文件保持不变；磁盘权限和空间问题不伪装成网络失败。所有镜像使用原官方元数据给出的 SHA 摘要验证，TLS 验证保持启用，不依赖镜像自己提供的摘要。未带官方摘要、未知 URL、带查询凭证的 URL 不加入镜像。目前 Fabric 动态生成的服务端 JAR、Paper 仍保留原流程，不声称全资源都已镜像。
- Vanilla 使用 Mojang 元数据及 SHA-1 校验；Paper 使用官方稳定构建及 SHA-256 校验；Fabric 使用官方 Loader 服务端启动 JAR。
- Forge 使用官方推荐 / 最新安装器，支持 Minecraft 1.17+；NeoForge 使用官方 Maven 稳定版本，支持 1.20.2+。安装器通过 SHA-1 校验。当前 Forge/NeoForge 自动安装仅覆盖 1.x 正式版本，其他命名版本会明确报错。
- Forge/NeoForge 安装前解析已校验的安装器内 `install_profile.json` 与版本 JSON，去重支持库，在远端逐个下载并核验 SHA-1、长度和 Maven 路径；NeoForge/Forge Maven 和 Mojang libraries 地址可测速使用 BMCLAPI。预先将原版服务端与服务端映射放到安装器期望的目录，并写入已获取的版本元数据，避免 Java 安装器重复从失败线路拉库。无 URL 的内嵌库也检查摘要，未知格式/路径不放行。NeoForge 21.1.255 实际配置包含 70 个唯一库，本地解析与预下载模拟已验证；尚未在用户远端完成整套安装实测。若仍失败，顶部显示短摘要及退出码，详细安装器输出留在终端日志，结果区域限高可滚动，不把依赖列表撑满页面。
- 整个部署在同级暂存目录完成，下载失败清理本次文件，成功后移动到目标目录。目标目录必须为空，不覆盖已有世界。
- “部署并启动”会自动启动并确认运行状态。服务端作为后台进程运行，不会在机器重启后自动启动；未配置 systemd 或 Windows 服务。
- 文件安装成功即保存“已安装”连接资料，随后启动失败也保留服务器管理入口，不要求重做部署。每次启动记录控制台起始偏移与时间；立即退出、等待期间退出或等待超时自动取本次控制台尾部和本次启动的新崩溃报告，遮蔽凭据后显示在终端。错误摘要仅引用明确日志原因，不自动猜测内存或端口问题。通过管理页读取日志、调整设置后启动，不覆盖既有安装目录或世界。
- 启动 Java 前根据实际 `server.properties` 检查游戏端口与绑定地址，端口占用或非本机 IP 时停止并提示，检查后释放探测 socket，不自动杀进程、不自动更换端口。`server-ip` 通常留空，NAT 公网 IP 不应填作本机绑定地址；检查存在 TOCTOU 窗口，后续 Java 仍可能因其他进程抢占而失败。通过配置编辑器更改 `server-port` 后，同步远端元数据及本地游戏端口，原 RCON 凭据保留。若与 CPT 网站/域名网关同机部署，TCP 25565 已由网关使用，Minecraft 服务端需另选空闲端口，不能停止网关来抢占。

## 管理功能

- 启动、正常停服、重启、状态查询、最近 64 KiB 控制台日志。区分运行中、已停止和启动中 / 管理连接暂不可用。
- Fabric / Forge / NeoForge 的 Mod、Paper 的插件：PCL 列表展示、启用/禁用、Modrinth 按远端当前或待应用版本搜索。
- Mod/插件预安装允许服务器继续运行。下载到隔离队列并校验 JAR，不写入运行目录；下次显式重启，或已停服后的启动，统一安装。
- 待安装队列支持查看、取消，重复文件名拒绝再次入队；替换已有同名资源时备份旧文件。
- 批量应用前校验全部队列，校验或兼容性失败不改文件；文件移动中途失败回滚已移动项目并保留队列。
- 重启顺序：正常保存停服 → 等待进程退出 → 应用待配置和资源 → 启动。120 秒未退出时停止流程，不强杀、不应用。
- 中文配置面板标记未保存修改；存在未保存项时，重启需确认“保存并重启”，关闭正版验证仍单独确认风险。先校验修改与读取版本，再正常停服、备份保存并读回校验，最后应用队列和启动；停服或保存失败不继续启动。停服自动重排配置时保留最新无关项，待修改值发生冲突则保持停服并要求重新读取。单独启动不会静默忽略面板未保存项。
- HTTPS 地址远程拉取 JAR，可填 SHA-256；Modrinth 资源自动校验 SHA-512。
- 模组与插件也可通过“导入本地 JAR”选择多个文件上传。导入前校验归档与 SHA-256，远端再次校验，加入预安装队列而不直接修改运行中的资源目录。
- 依赖项显示并要求确认，不自动解析或安装所有依赖。插件/Mod 属于可执行代码，只应安装可信文件。
- `server.properties` 中文面板按连接与验证、游戏规则、性能、世界、资源包等分组，支持中文名称或英文键搜索，按值类型显示开关、选项和输入框；文件中的英文键名保持不变。读取后才允许保存，仅提交修改项，保留其他配置、注释和换行；配置被其他操作修改时拒绝覆盖，保存前要求停服并备份。
- 关闭 `online-mode` 需要单独确认账号冒用与 UUID 变化风险；中文面板中的 RCON 和管理协议配置由程序保护，密码与密钥不显示。
- 保存游戏端口后同步远端元数据、本地连接资料和已有的待应用运行配置，避免重启写回旧端口；未修改端口时保留用户专门准备的新端口。保存中途写入失败时恢复已写入文件和旧备份。启动、重启与状态查询同步当前端口，重新打开页面或重启 CPT 后沿用已保存资料；应用运行配置不重写无关 properties 行。
- 在线玩家查询、封禁、解封、踢出、授予/撤销管理员、白名单增删。玩家操作通过远端 localhost RCON 执行，服务器需处于运行状态。
- 服务器配置页单独读取和准备 Minecraft / 加载器 / Java / 内存 / 游戏端口。准备时不改运行配置，重启时应用。
- 更换 Minecraft 版本或加载器前，必须禁用旧的已安装资源、取消不兼容队列；停服后自动备份服务器数据，再应用新产物。世界升级可能不可逆，备份不代表任意降级兼容。
- 启用/禁用和 properties 编辑要求停服；预安装无需停服。同一目录有并发操作时拒绝第二个操作。

## 安全与限制

- SSH 密码不保存，连接资料仅保存主机指纹等非密码信息。私钥认证已移除。
- RCON 不加密。管理请求在远端通过 `127.0.0.1` 发起。一键部署确认弹窗会告知系统防火墙改动：Linux 在 IPv4/IPv6 INPUT 链中阻止非 loopback 的 TCP 25575、允许游戏端口；Windows 使用系统防火墙规则。以后启动会重新检查规则。不会清空已有防火墙规则或修改云平台安全组。
- Linux 修改防火墙前预检权限、IPv4/IPv6 工具及 INPUT 链，使用 `-w 10` 等待规则锁。部署流程已要求 root，代理在其他调用下仍兼容免交互 sudo。先保护两种地址族的 RCON 端口，再允许游戏端口，新增规则后重新校验；失败不继续部署或启动。报错显示系统 stderr 并区分提权失败、NET_ADMIN 权限、锁竞争和后端/内核不兼容。SSH 密码不自动用于提权，不修改 sudoers、不关闭防火墙、不自动切换 iptables 后端。非 root SSH 用户必须具有 sudo 权限或能通过 root 密码完成 su；容器/受限 VPS 即使是 root 也可能缺少修改防火墙的能力。
- RCON 使用随机密码、25575 端口，适合每台主机部署一个受管服务端；多个实例须规划不同管理端口，目前界面没有独立 RCON 端口设置。
- 文件管理只能访问受管目录，不接受任意路径；玩家名与指令分别校验，不能注入其他控制台命令。
- 暂不包含自启动服务、整合包部署、任意配置文件浏览或 Forge 1.16 及更早版本安装器。
- 新界面完全使用 PCL 的左导航、MyCard、MyListItem、MyComboBox、MyCheckBox、MyTextBox、MyButton，密码框沿用原登录页全局模板。
